## Findings

All reported runtime failures below were reproduced against isolated PostgreSQL test databases. Independent `gpt-6-luna` verifier tests confirmed IDs 1–6. IDs 7–8 reproduced in request tests from the error-handling pass and again in the orchestrator rerun, but the agent-thread limit prevented separate Luna verifiers for them.

| ID | Area | Severity | File and line | Reproduction | Status |
| --- | --- | --- | --- | --- | --- |
| QA-1 | Input / report publishing | Medium | `core/forms.py:189`; `core/models.py:20` | Complete the wizard with an 81-character place name; POST review returns 500 `DataError` because the form allows 100 but the report column allows 80. | Confirmed, independent Luna verifier |
| QA-2 | Input / registration | Medium | `core/forms.py:81,93`; inherited username column at `core/migrations/0001_initial.py:27` | Register with a valid 163-character email; registration form accepts it, then saving email into the 150-character username column returns 500. | Confirmed, independent Luna verifier |
| QA-3 | State / draft creation race | High | `core/views.py:130-140,394`; `core/models.py:39` | Synchronize two first-time `GET /reports/new/` requests for one user: both return 302 and create drafts. A later `/r/<uuid>/found/` scan returns 500 from duplicate draft lookup. | Confirmed, independent Luna verifier |
| QA-4 | State / concurrent publish | High | `core/views.py:201-202`; `core/services.py:122-152` | Pause a valid step-2 POST before `draft.save`; publish that draft in a second request, then resume the step POST. It recreates the deleted draft; replaying step 5 creates a second report. | Confirmed, independent Luna verifier |
| QA-5 | Upload error handling | Medium | `core/views.py:193`; `core/images.py:14-15` | POST a valid but truncated JPEG at wizard step 2: HTTP 500. An intact JPEG control succeeds. | Confirmed, independent Luna verifier |
| QA-6 | Search input / PostgreSQL | Medium | `core/views.py:103,108` | Authenticated `GET /reports/?q=%00` returns 500 `DataError`; empty and valid search controls return 200. | Confirmed, independent Luna verifier |
| QA-7 | Private media errors | Low | `core/views.py:250,262,315-316` | Request an owner-authorized photo or QR image whose database row points to a missing file; endpoint returns 500 instead of 404. Report photo, draft photo, and QR image routes all reproduced. | Confirmed, direct request-test rerun; separate verifier unavailable |
| QA-8 | Management input | Low | `core/views.py:372` | Staff POST `/management/` with a non-integer `report` value returns 500 during ORM lookup; reproduced for `abc`, empty, fractional, and SQL-like strings. | Confirmed, direct request-test rerun; separate verifier unavailable |

Suggested fixes: align form and database limits; validate email length before assigning username; serialize/uniquely constrain active-draft creation and reject stale step saves after publish; fully decode uploaded images during validation and turn decode errors into a field error; reject NUL search input; translate missing private storage files to 404; validate the moderation ID as an integer before lookup.

The existing browser suite has a stale assertion, not an app defect: `core/test_browser.py:110` looks for `.auth-art img`, while the current login template has no artwork image. The baseline run fails there. A current-flow Chrome test passed at 320, 390, 768, and 1280 pixels, including login retry, password toggle, remember-me, redirect, logout, and registration. Suggested fix: update that assertion to check the current page structure. This is a test maintenance gap; excluded from the runtime bug IDs.

## V2 resolution after approval

All eight original failures are covered by passing tests in the current v2 tree.
Several fixes were already present when v2 was re-inspected: migration 0006 widens
report locations and email login usernames; uploaded images are decoded during
validation; search controls and management IDs are screened; missing media returns
404; stale wizard saves use update-only persistence; current login assertions replace
the obsolete artwork selector. Migration 0006 is applied locally.

One incomplete fix remained: QR scans tolerated duplicate drafts, but concurrent
first visits still created two. Draft acquisition now locks the owner's existing
row before selecting/creating a draft, shared by new-report, QR-scan, and edit paths.
The two original race tests now require exactly one active draft. Additional tests
cover concurrent QR/new-report requests and concurrent edits of the same report.
Existing duplicate rows are preserved; the newest applicable draft is reused.

Final command: `.venv/Scripts/python.exe manage.py test core --noinput --verbosity 1`.
Result: **147 tests passed in 40.600s** on PostgreSQL, including Chrome checks.

drift check reported `No changes detected`. The full 145-test suite also passed
immediately after the draft-acquisition fix, before the two extra race tests were added.

Status documentation now distinguishes implemented production settings from unfinished
deployment. Password reset, profile management, notifications, management pagination,
login throttling, production backups, in-app help, production security review and
